Full re-analysis of the app (src), the Firebase functions (functions/src), the native alarm
module and the project configuration, done before the M7 device test. Eight area reviews (alerts,
calendar sync, tasks and To Do, assistant, data layer and auth, UI, functions, integrations) plus
the mechanical gates. Every finding below was verified against the code path before it was
changed. Line numbers are as of commit `6f37f97` (the push-hold fix) unless stated.

## 2. Fixed in this pass

### Performance (user-visible jank)

- Every time-zone check built a new `Intl.DateTimeFormat`; the device zone was read from the
  native side on every formatted time. `isValidTimeZone` is memoized and `getDeviceTimeZone`
  cached for 10 s (`src/core/time.ts`).
- Recurring meetings were re-expanded over 377 to 460 days on every 30 s or 60 s clock tick on
  the dashboard and the meetings list, and the list item received the clock as a prop so every
  row re-rendered each minute. Expansions are keyed on the local day; the item receives an
  `inProgress` boolean (`DashboardScreen`, `MeetingsListScreen`, `CalendarScreen`,
  `MeetingListItem`).
- Daily and weekly rules walked every occurrence since the anchor before reaching the window. The
  generator now starts near the window (`src/core/recurrence.ts`, `candidateDates`), except for
  counted rules, which must number their occurrences from the anchor.

### Calendar sync

- Outlook, fresh install or second device: the first pull matched the listing against an empty
  cache and imported this user's own pushed events as foreign meetings; deleting such a duplicate
  deleted the real event. Own events are recognised by their `transactionId` (`mgev-...`, now
  selected), series masters included, and the session-start pull waits up to 10 s for the server's
  meetings (`outlook/sync.ts`, `outlook/api.ts`, `calendar/engine.ts`, data engine
  `waitForMeetingsBaseline`).
- Outlook all-day events east of UTC landed one day early (`outlook/mapping.ts`,
  `allDayLocalDate`).
- Outlook invitations for meetings with an address AND a video link carried no join link; the
  body now gets the same join block the Google writer appends, stripped again on import.
- Google and Outlook `connect()` wiped the queued pushes; the queue now survives a reconnect.
- A change pulled from one provider is queued for the other provider's copy of the same own
  meeting (`calendar/engine.ts`, `onMeetingChanged`, reason `imported`).
- Google 412: an invisible remote change (an RSVP) no longer discards the local edit; the write is
  retried without the stale etag. Masters Google derives from ours (`_R...` suffix) are recognised.

### Microsoft To Do (M7)

- The public `tasksRepository` wrapper dropped the write options (`data/engine.ts`), so every
  import lost its deterministic id and `source: 'todo'`: Stop sync left imported tasks behind,
  Start sync pushed them back as new tasks, two devices created twins, assistant tasks were stored
  as manual. One-line fix, covered by the existing engine tests through the repository now.
- Links are learned on import, so Change list deletes the old copy for tasks this device never
  pushed; a leftover copy returned by the idempotent id is never re-linked.
- A To Do reminder after the due date (or more than seven days before it) rang on the due date;
  the reminder instant is kept and the due date moved onto it.
- Date-only values at UTC+13 and beyond shifted a day; exact UTC midnight is taken as its date.
- A 403 on one task blocked the whole sync forever; it now counts attempts like a transient error.
- Disconnecting Outlook turns the To Do sync off (same account; a later connect with another
  account must not resume against old list ids).

### Microsoft sign-in

- A token refresh in flight at sign-out could re-persist the deleted refresh token and hand user
  A's access token to user B; the refresh is keyed by uid and cancelled by `clear()`.
- A keystore write failure while rotating the refresh token counted as a revoked consent and
  disconnected Outlook and To Do; it is now logged and the previous token is tried next time.

### Assistant

- Typed Spanish `si` (no accent) was listed as a qualifier ("if"), so it never executed while the
  model's reply said "confirming"; `si` qualifies only when a condition follows it, and a blocked
  resolution now gets an honest server reply (`resolve_tap`).
- A plain "yes" ran every pending proposal in the thread; it now resolves the newest reply's
  proposals only (`selectLatestPendingActionIds`, `confirmLatest`, voice path included).
- A bulk move that failed on one meeting reported a plain failure although the others moved; a
  per-meeting rejection is reported as skipped, a transient failure still fails the action for a
  later resumed retry.
- `create_task` had no deterministic id (twins on a retry after a crash); it uses the same
  derivation as meetings.
- OpenAI `insufficient_quota` was mapped as rate limiting (warn log, free retries); it is a
  configuration error now.
- A task linked to a meeting created in the same reply could run before the meeting existed; the
  mapped actions are stably sorted so the meeting goes first.

### Data layer

- Preferences sends were full documents built from the keys the running build knows: an older
  build on a second device reset new keys to defaults. Unknown keys now ride along, and a
  `permission_denied` on a preferences write waits for the rules deploy instead of being dropped.
- Transaction contention exhaustion arrived as `failed-precondition` and was treated as a
  permanent rejection (edit dropped and rolled back); it is now `conflict`, retryable.
- One stuck document blocked every other queued write for up to about an hour; non-network
  failures defer that document only.
- The outbox row is read on its own so an oversized or corrupt row cannot sink the whole session.
- Android AsyncStorage limit raised from 6 MB to 50 MB (`plugins/withAsyncStorageDbSize.js`, also
  in the local `android/gradle.properties`).

### Alerts

- iOS: the 60 meeting notifications plus 20 task reminders plus 2 briefings exceeded the 64 cap;
  the meeting budget now subtracts what the others hold at reconcile time.
- Native module: a reconcile planned before an alarm's fire instant re-set it after the receiver
  had already posted it, so the alarm sounded twice; the fired record is checked first (Kotlin
  change: ships with the next APK and store build).
- The home card asked for the exact-alarm permission forever; the real
  `canScheduleExactAlarms()` state is reported (`granted` / `denied`).

### UI

- Deleting a meeting from its details screen flashed "Meeting not found" during the back
  animation; the last version stays on screen while leaving.
- "Next occurrences" on the details screen used a frozen `new Date()`; it follows the clock.
- Task due times were formatted as device wall clock while the overdue rule used the task's zone;
  both use the same instant now.

### Server

- WhatsApp session documents of unlinked or flood-only phones never received `updatedAt` and so
  were never purged; the first counter write sets it.
- A message that failed after its dedupe claim produced no reply and no redelivery; the user now
  gets the generic error text.
- Account deletion removes the `zoomMeetings` ownership entries and records their ids on the
  deletion record; the restore replay removes the WhatsApp link data too.
- `google-auth-library` is a declared dependency (it was resolved through firebase-admin's tree).

## 3. Not changed, with the recommended countermeasure

- **Outbox as one AsyncStorage row.** Every write and every acknowledgement rewrites the whole
  queue; a first import of a thousand occurrences makes that quadratic, and a row over about 2 MB
  cannot be read back on Android. The storage limit and the isolated read above remove the
  session-killing case; the structural fix is one key per entry (or doc-id-only entries read from
  the cache at send time). Medium change in `data/engine.ts`, `cache.ts`, `outbox.ts`.
- **Full-collection meetings listener.** Every cold start downloads every active meeting ever
  created; pull-to-refresh re-reads them all. Bound the listener to a date window and query older
  documents on demand; make refresh a bounded query. Medium change, touches the first-baseline
  deletion logic.
- **Older client replacing newer documents.** A build whose schema rejects a newer document edits
  its cached copy and the send deletes and recreates the server document without the new fields.
  Define "legacy shape" structurally instead of by schema validity.
- **Device clock drives tombstone purges and last-writer-wins.** Let `dailyMaintenance` own the
  purge; consider server timestamps for `updatedAt`.
- **Android 6 to 11 Doze throttling** can defer the T-0 alarm a few minutes on a stationary phone;
  `setAlarmClock` would avoid it (visible alarm icon, exempt from the throttle). Native change.
- **MEDIUM alerts on Android 13 and below stay in the shade** until the app is opened (sticky,
  no timeout); either drop `sticky` for MEDIUM or let the background task dismiss ended ones.
- **Cold start cost**: every function instance loads the OpenAI SDK; lazy-import it in the ping
  and the client factory.
- **Chat text-to-speech** stops an alarm readout in progress; track what the chat started.
- **Typed consent that resolves to confirm** runs inside the request chain, so a share sheet
  blocks the next message silently; run the resolution outside the chain.
- **`android/` is tracked** although `.gitignore` ignores it, which keeps `git status` noisy and
  ships a local-test prebuild; `git rm -r --cached android` when convenient (EAS is unaffected).
- **Rules tests** need Java 21 installed on the build machine.
